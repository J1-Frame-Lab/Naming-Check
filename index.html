01 / 19

Overview.

Naming Check keeps an Unreal project's asset names consistent with a convention you define: SM_ for static meshes, T_ for textures with a suffix that says what the texture holds, MI_ for material instances, and so on for 105 asset classes out of the box. It scans a folder or the whole project, shows every name it would change and what it would change it to, lets you correct any of them, then renames safely, with a journal that can undo the whole run.

It is built for real projects: marketplace packs with three conventions mixed together, Substance exports, Cyrillic in file names, packed textures nobody labelled, tens of thousands of assets, a Perforce workspace where every file is read-only until it is checked out. Each of those has a specific answer in this manual.

What it never does

  • It never overwrites an existing asset. If two assets would end up with one name, or the name is already taken, they are skipped and you are told why.
  • It never renames anything on save. Validation only reports.
  • It never submits, reverts or resolves in source control. It checks files out; the rest is yours.
  • It never guesses. A name it cannot decide, such as a packed texture with an unknown channel order, goes to Review with the reason and stays as it is.
  • It never renames a folder, and it renames levels only when you turn that on (chapter 15).
  • It never deletes a redirector that something still uses.

The window

Open it from Tools > Naming Check > Open Naming Check, or right-click a folder in the Content Browser and choose Naming Check > Scan This Folder and Subfolders. It has four pages on the left:

PageWhat it is for
LinterScan, review what would change, correct any name, rename.
RulesEverything the tool uses to decide a name, as editable tables.
HistoryEvery rename the tool made, and Undo for the latest run.
ReportsRead-only reports: project audit, textures, meshes, folders, active rules, the rename plan.
New in 1.1.0

Find / Replace in the Linter. Remove Words, Forbidden Words and Structure Templates on the Rules page. Packed textures read channel by channel (OcclusionRoughnessMetallic becomes _ORM). A reason on every Review row. Rules an update adds reach projects with older saved rules. Reports read the Asset Registry instead of loading every mesh. Renames act only on the rows the table shows, and a big rename runs one chunk per editor frame while the editor stays usable.

02 / 19

Install.

Requirements

  • Unreal Engine 5.5, 5.6, 5.7 or 5.8 on Windows 64-bit.
  • The Python Editor Script Plugin and Data Validation plugins. Both ship with the engine and are enabled automatically as dependencies. The naming logic runs in the editor's own Python; there is nothing else to install.
  • Editor only. Nothing is added to a packaged game.

Install from Fab

  1. Install to your engine

    In Fab, or in the Epic Games Launcher's library, choose Install to Engine and pick the engine version you work with.

  2. Enable it in the project

    Open the project, go to Edit > Plugins, search for Naming Check (category Editor), tick it and restart the editor when it asks.

  3. Find your config

    On first start the plugin writes <Project>/Content/Python/naming_check_config.py. That file is yours: plugin updates never overwrite it, and rules an update adds still reach you (chapter 15).

Install a compiled build from a teammate

  1. Close the editor

    A plugin cannot be dropped into a running project.

  2. Unzip into the project's Plugins folder

    You should end up with <Project>/Plugins/NamingCheck/NamingCheck.uplugin. If a NamingCheck folder is already there, delete it first; never merge two versions.

  3. Start the editor

    Check that Naming Check is ticked under Edit > Plugins. If the editor asks to rebuild modules, the build was made for another engine version.

Careful

A compiled zip goes into the project's Plugins folder, not the engine's. A Fab install is the one that goes into the engine.

Where things live

PathWhat
Content/Python/naming_check_config.pyYour convention file: the rule tables and every switch. Created on first start, never overwritten.
Config/naming_check_rules.jsonThe rules you saved on the Rules page. Once it exists it overrides the rule tables of the config file. Commit it so the team shares one convention.
Saved/NamingCheck_RenameJournal.jsonThe rename journal: the last 20 runs, on this machine only.
Saved/*.csvReport output, the rename plan and the compliance history (chapter 17).

Uninstall

Untick Naming Check under Edit > Plugins, or remove the plugin folder. Your config file, the rules json and the journal stay behind on purpose; delete them too for a full removal.

03 / 19

Quick start.

Work folder by folder before you touch the whole project. This sequence keeps a first run boring, which is what you want.

  1. Exclude what is not yours

    Open the window, go to Rules > Excluded Paths and add every marketplace pack you intend to update later. Renaming vendor content means the next pack update overwrites your work. Press Save Changes.

  2. Scan one folder

    In the Content Browser, right-click a folder that is yours and choose Naming Check > Scan This Folder and Subfolders. The Linter opens with the results as a tree.

  3. Read the proposals

    Every row shows the current name and the proposed one. If something looks wrong, it is almost always a rule, not a bug: check Junk Suffixes and Legacy Prefixes first. A Review row tells you why in the tooltip on its status.

  4. Remove the noise

    A vendor tag in every name, like verybadnaming_Lamp1? Type it in Find, leave Replace with empty and press Apply to All Shown. For a word that should never survive in this project, add it to Rules > Remove Words instead.

  5. Tick what to rename

    Rows that need a rename start ticked. Untick the ones you want to leave, or tick a folder bar to cover everything under it.

  6. Rename Ticked + Fix Redirectors

    The renames happen and every changed asset is saved. If the rename left redirectors, Unreal's redirector report opens about a second later for exactly those; choose Delete or Keep there.

  7. Check the result

    The table re-scans by itself. Nothing left that needs a rename means you are done with that folder. If anything went wrong: History > Undo Last Run.

Tip

Run Reports > Project Audit once before all of this. It tells you the scale: how many assets, what share is compliant, which classes have no rule yet.

The Linter.

Everything about renaming happens here. From the top: what was scanned, the summary line, the filters, the options that shape the proposals, Find / Replace, the results tree, and the buttons that act on the ticked rows.

Choosing what to scan

ControlScans
Use Current SelectionWhatever is selected in the Content Browser: assets, folders, or both.
Scan Whole ProjectEverything under /Game, minus the excluded paths.
Right-click a folder > Scan This Folder and SubfoldersThat folder and everything below it. Opens the window if it is closed. With several folders selected, the first one is scanned.
RescanThe last scan again with the current options. Also happens after every rename and after saving rules. Discards hand edits and Find / Replace previews.

The Scan target field shows what the table holds: whole project, a folder path, Content Browser selection, or the assets of the last import.

Reading the results

The summary line counts everything: Showing 9024 of 14692 | Ticked | Needs Rename | Compliant | No Rule | Review | Error | Skipped. Results are grouped by folder. A chain of folders with no assets of their own is collapsed into one bar, so Pack/assets/Thing is one row, not three. Assets that sit directly in the content root get a bar of their own, /Game (assets in the content root).

Tip

Click a column header to sort, again to reverse (every column except the tick and Size). Untick Group by folder for one flat list, handy when sorting by Type across a whole scan.

Filters and search

FilterOptions
StatusIssues only, All (default), Needs Rename, Review, No Rule, Error, Compliant, Skipped (on purpose). Issues only hides Compliant and Skipped rows.
TypeAll types, one asset-type group (Textures, Static / Skeletal Meshes, Materials, Blueprints, VFX, Audio, Animation, Cinematics / Sequences, Foliage / Landscape, Data / Input), or Other (no group).

Filters also limit what gets renamed: a rename acts only on the rows the table shows (see Renaming, below).

Options that change the proposed names

The Proposed names row holds four options. Each one re-scans immediately, so the New Name column previews the effect before anything is renamed.

OptionEffect
Nanite tag on meshesMeshes with Nanite on get _Nanite appended; meshes without it lose the tag if they had one. Re-running never stacks the tag.
Parent tag on material instancesThe parent material's name is folded in: MI_Chair_01 with parent M_MasterWood becomes MI_MasterWood_Chair_01.
Version suffixas is, V1/V2 -> A/B or A/B -> V1/V2. A compliant name whose suffix would change becomes a Needs Rename row. A/B to V1/V2 skips textures and converts only the letters A to H.
Size tagoff, centimetres or metres. Measures every mesh and shows the footprint in the Size column; you choose per row which meshes carry it.

Ticking rows

Ticking is how you say which proposals actually get applied. Use whichever gesture your hand reaches for:

  • Shift-click between two ticks. Tick one box, then Shift-click another further down: everything in between takes the same state. The first tick stays the anchor, like in a file manager.
  • Highlight, then tick once. Click a row, Shift-click or Ctrl-click others to highlight a block, then tick any box inside it: the whole block follows. Space toggles the highlighted rows while the table has focus, and Ctrl+A highlights every row.
  • Tick a folder bar. It covers every asset under it, at any depth.

The buttons Tick Highlighted, Untick Highlighted, Tick All and Untick All do the same with the mouse. All means everything the current filters show.

The size tag

Some conventions want a mesh's footprint in its name: SM_Wall_400x300 in centimetres or SM_Wall_4mx3m in metres. Set Size tag to the unit you want and every mesh is measured; this can load meshes, so it takes a moment. The Size column then shows the value and a tick. Tick the meshes that should carry it; a size tick also ticks the row, so a correctly named mesh that only gains a size is included. Shift-click ranges work here too, and Size on Highlighted / Size off Highlighted act on a highlighted block.

Note

A size tag already in a name is stripped from the proposal first, wherever it stands, so re-running never produces two. Axes, rounding and decimals are set in the config file (chapter 15).

Find / Replace

The same search-and-replace as the Content Browser's Batch Rename, applied to the proposed names. Type a word in Find, leave Replace with empty to remove it or type a replacement, then:

ButtonChanges the proposed names of
Apply to HighlightedThe highlighted rows, or everything under a highlighted folder bar.
Apply to All ShownEvery row the filters show. Pressing Enter in Find does the same.
  • The class prefix is never searched: finding SM cannot strip SM_.
  • The result is tidied like every proposed name, so removing verybadnaming from SM_Verybadnaming_Lamp1 gives SM_Lamp1.
  • Changed rows are ticked; nothing is renamed until you press a Rename button. Rescan puts the proposals back.
  • A name that would be left empty keeps its proposal, and the status line says how many.
  • Not case-sensitive unless Match case is ticked. Skipped and Error rows are never touched.
Tip

Find / Replace is for this scan. A word that should go from every name, every time, such as a vendor tag or a pack name, belongs in Rules > Remove Words.

Renaming

ButtonDoes
Rename TickedRenames the ticked rows the table shows and saves every changed asset.
Rename AllEvery row the table shows that needs a rename, plus rows you changed, ticked or not.
Rename Ticked + Fix RedirectorsRenames, then about a second later runs the engine's redirector fixup for exactly the redirectors this rename left. No other redirector, asset or level is touched. Unreal's report lets you choose Delete or Keep. Often there is nothing to fix up, because Unreal removes a redirector itself when it could update everything that used the asset.
Rename All + Fix RedirectorsThe same for every row the table shows.
Fix Up RedirectorsEvery redirector in the scanned folders, through the engine's fixup and its report. Changes no names.
Export CSVThe rows shown, as sorted, with the names that would be applied and the review reasons.
Careful

Renames act on what the table shows. A row the search or a filter hides is never renamed, ticked or not, so searching one folder renames only that folder. The confirmation says how many hidden rows were left alone. Clear the search and set the filters to All to rename the whole scan.

A batch of 50 or more asks before it starts (CONFIRM_THRESHOLD). A rename larger than one chunk, 100 assets or fewer when they are big textures, runs one chunk per editor frame: the editor stays usable and the status line counts the progress.

The line to the left of the buttons is the status line. Every click writes there, for example Renamed 12 asset(s), 2 skipped as collisions, Removed 'verybadnaming' from 37 name(s) or Nothing to rename - tick at least one row that needs a rename. If a button seems to do nothing, read that line first.

Tip

A name you typed goes through exactly the same checks as a generated one: collision protection, source control check-out, the journal, plus a check for characters Unreal does not allow in a name, such as spaces, dots and slashes. Correcting a name by hand is never less safe than accepting the proposal.

Export CSV opens a save dialog that starts on Saved/NamingCheck_Linter.csv with the columns Status, CurrentName, NewName, Type, MatchedRule, Path, Note.

The Rules page.

Everything the tool uses to decide a name, as editable tables. Pick a category on the left; the table on the right lists its rows, each with an Enabled tick, so you can switch a rule off without losing it.

CategoryWhat the rows mean
Class PrefixesWhich prefix each asset class must carry. The class is picked from a list, so a typo cannot silently kill a rule.
Texture SuffixesSuffix by compression setting, used only when the name itself says nothing about the texture type.
Suffix AliasesWords at the end of a texture name that mean a suffix: normal and nrm both become _N. Keys are lowercase.
Texture GroupsPrefix by texture group: a UI texture gets T_UI_ instead of T_.
Junk SuffixesMarketplace leftovers stripped from the end of names. Do not add _v1, _Low or _High: they mark real variants.
Legacy PrefixesPrefixes you no longer use, stripped so the new prefix is not stacked on top of them.
Remove WordsWords dropped from every proposed name wherever they stand as a whole word, in any case. Removing Lamp leaves Lampshade alone.
Forbidden WordsA name holding one of these as a whole word goes to Review instead of being renamed. The examples start unticked.
Structure TemplatesThe order of a name's parts, per class (chapter 10). Off until a row is ticked.
Excluded PathsNothing under these folders is scanned, reported or renamed. Put your marketplace packs here.
Excluded NamesAssets whose name contains any of these are skipped.

Editing, saving, sharing

  • Add Rule and Remove Rule act on the current category; Remove takes the highlighted rows.
  • In Class Prefixes the class comes from a list of every asset type your editor can create or import, plugins included, with the Content Browser's name beside it where it reads differently, for example MaterialFunctionMaterialLayer (Material Layer). A new row starts on a class that has no rule yet.
  • The Status column flags problems as you type: empty, duplicate, no prefix, prefix should end with _, and for templates no template, needs {Name} and {Prefix} goes first. Save Changes stays disabled while an enabled row has a problem. A template with an unknown or repeated slot is refused on Save, with the reason in the status line.
  • Save Changes writes Config/naming_check_rules.json, and the Linter re-scans with the new rules at once.
  • Revert Changes goes back to the last saved state. Reset to Defaults deletes the saved file, with no confirmation; the tool returns to the config file and the built-in defaults.
  • Import CSV / Export CSV move one category in or out (columns Enabled, Key, Value, Extra, Description). An import replaces the category and stays unsaved until you press Save.
  • Export All... / Import All... move every category at once as one rules file, stamped with the tool version and the project name: the way to carry a convention from one project to the next. A partial file replaces only the categories it contains.
Note

The line under the search box says where the rules came from: the saved rules file, or built-in defaults. Once naming_check_rules.json exists it replaces all eleven rule tables of the config file; the switches (validation, source control, limits) are always read from naming_check_config.py.

Note

When a plugin update adds rules, a project with a saved rules file shows them as new in 1.1.0, or new in 1.1.0 (was GC_) for a changed default. They are already in effect; Save makes them part of your file, or untick any you do not want.

Careful

The plugin does not check the rules file out of source control. On a Perforce workspace, check out Config/naming_check_rules.json before you press Save, then submit it like any other file.

06 / 19

History and undo.

Every rename run the tool made, newest first. A run expands to its renames, old -> new (folder), up to 200 lines; the journal file keeps every one. The top run is expanded and marked <- next Undo.

ButtonDoes
Undo Last RunRenames everything from the top run back to its old name, through the same safeguards the rename used. The run then leaves the list. A run larger than one chunk is undone one chunk per editor frame, with the progress on the page. From 50 renames up it asks first.
RefreshRe-reads the journal.
Clear JournalForgets every run, with no confirmation. Undo is no longer possible for them.
Recover from Log (preview)For a run the journal no longer has: pick an editor log from Saved/Logs and see which of its renames are still in place. Prints the plan to the Output Log, changes nothing.
Recover from Log (apply)Puts those renames back. Recorded as a run of its own, so Undo Last Run reverses it.

Why only the top run

Runs build on each other. If one run renamed A to B and the next renamed B to C, undoing the first alone has nothing to rename: B is gone. Undo the top run, then the next, in order.

The journal is per machine

It lives in Saved/, which is not under source control. You can undo your own runs; a teammate who synced your renames cannot, and that is what the depot's history is for. Assets that were moved or renamed again since a run are skipped by Undo, with a count in the log; a run that could only be partly undone stays in the list, marked (partially undone), for a second Undo.

Every report is read-only. Results go to the Output Log, and most of them to a CSV in the project's Saved folder. Reports read the Asset Registry and load an asset only when a value is missing there.

The mesh report flags four things: NEEDS LODs (5,000 triangles or more, a single LOD, no Nanite), WEAK REDUCTION (LOD1 keeps more than 70% of LOD0's triangles), REDUNDANT (Nanite on and more than two LODs) and OVER-LODDED (fewer than 500 triangles and more than two LODs). The thresholds are in the config file. It is a report rather than a name tag on purpose: LOD counts change every time someone regenerates them, so a _LOD4 baked into a name goes stale silently.

Note

Most report lines in the Output Log start with the report's prefix: NamingCheck:, NamingCheckAudit:, TexReport: or MeshReport:. Filter the log by the one you ran, or clear the filter to see the listing lines in between.

09 / 19

How a name is decided.

Knowing the order helps when a proposal surprises you. For one asset:

  1. Expected prefix

    From the class's rule. A class with no rule takes its nearest ancestor's. A Blueprint is typed by its parent: component AC_, interface BI_, function library BPFL_, packed level actor PLA_, AI controller AIC_, behavior tree task, service and decorator BTTask_, BTService_, BTDecorator_, anything else BP_. A Material Layer or Layer Blend has its own rule (ML_, MLB_).

  2. Texture group

    A texture in the UI group gets T_UI_ instead of T_.

  3. Remove words

    Every word in Remove Words goes first, wherever it stands as a whole word, so everything after this sees the name without it. If nothing but the prefix would be left, the name stays as it is.

  4. Strip stacked prefixes

    See the table below; this is where most surprises live.

  5. Find the texture type word

    Looks past size and flavour tokens: _disp_1k, _nor_gl_1k, T_Height, Roughness50 are all understood. Channel words run together are read letter by letter (Packed textures, below).

  6. Clean the name

    Cyrillic transliterated, never deleted. Spaces and symbols become underscores, double underscores collapse, junk suffixes go, PascalCase is applied. A name made only of symbols is left alone rather than turned into nothing.

  7. Texture suffix

    The word from step 5 wins; otherwise the compression setting decides; a packed mask with no hint goes to Review, never guessed.

  8. Opt-in tags

    Nanite, material-instance parent, size: only when you turned them on.

  9. Forbidden words

    A name that holds a word from Forbidden Words goes to Review, with that word as the reason.

  10. Structure template

    If a template covers the class, the parts are put in its order (chapter 10). A name whose parts cannot be told apart goes to Review instead.

  11. Apply the prefix

    Not case-sensitive, so sm_rock becomes SM_Rock.

Packed textures

A packed texture holds a different map in each channel, and Unreal stores nothing that says which. The name is the only evidence, so the tool reads it carefully and refuses to guess:

  • A known alias wins: _ORM, _RMA, _ARM, packed, and OcclusionRoughnessMetallic (_ORM).
  • Channel words run together are read letter by letter (Occlusion, Roughness, Metallic, AO, Height, Specular, Emissive, Opacity) and accepted when they spell a suffix the aliases already produce: AORoughnessMetallic gives _ARM, RoughnessMetallicAO gives _RMA.
  • Three or more channels in an order no rule covers go to Review with the letters they spell. Add the word under Suffix Aliases once and every texture named that way follows.
  • A TC_Masks texture whose name says nothing goes to Review. If your project always packs one way, set TC_MASKS_DEFAULT_SUFFIX in the config file.

Structure templates.

Conventions disagree on order. One studio writes SM_Rock_01_A, the next SM_Rock_A_01, and a pack you bought does a third thing. A structure template says which order this project uses, per class, and you can swap it any time. Templates are off until you turn one on: Rules > Structure Templates lists three examples, unticked; tick one, press Save and the Linter re-scans with it.

SlotFilled by

  • Start with one class, look at the proposals, then widen to *. A template changes many names at once: that is the point, and the reason to look first.

Safety.

What protects the project while the tool renames a thousand assets:

  • Check never changes anything. Every check, report and plan is read-only.
  • Nothing is overwritten. A target name held by another asset, wanted by several assets, or held by a redirector something still points at is refused and reported. The tool never picks a winner. The Output Log lists them, and naming_check.check_collisions_all() in the Python console gives the full breakdown.
  • What you see is what gets renamed. The Linter's Rename buttons act on the rows the table shows; the confirmation says how many hidden rows were left alone.
  • Batches of 50 or more ask first (CONFIRM_THRESHOLD). Undo exists either way.
  • Every rename is saved immediately. Unreal saves most of what it renames itself; the tool saves whatever is left unsaved and reports anything it could not save.
  • Renames run in verified chunks. Each chunk is checked against the live project just before it runs, confirmed afterwards and journalled before the next one starts, so only renames that really happened can be undone. What an asset uses is renamed before the asset itself, so no asset is saved holding a path the same batch changes later.
  • Big renames keep the editor usable. More than one chunk runs one chunk per editor frame, and what each chunk loaded is unloaded before the next. Chunks of big textures and meshes are smaller (about 2 GB of them at a time), and a rename stops between chunks when the computer runs low on memory: what was done is saved and journalled; restart the editor and run it again for the rest.
  • A broken asset does not break the batch. An animation with a missing skeleton is skipped with the reason; the others go through.
  • Problems are found before the batch, not in the middle of it. Files the engine cannot write and names that would make a file path longer than 200 characters are reported and skipped up front.
  • Typed names are checked for characters Unreal refuses. A case-only change (SM_rock to SM_Rock) is a real rename; its file name on disk is checked too and fixed when Unreal kept the old case (restart the editor before editing those assets).
  • Redirectors. Every rename leaves a redirector at the old name, which keeps other assets' references working. A redirector Unreal refuses to save is deleted only when nothing uses it; one a closed level still uses is kept and listed. An unused redirector sitting on the target name is removed so the asset can take it. Everything else goes through Unreal's own fixup and its report, and + Fix Redirectors takes only the redirectors its own rename left.

Source control and teams.

On a studio workspace every asset is read-only until it is checked out. Without help the tool would report the whole project as locked and rename nothing. So with SOURCE_CONTROL_AUTO_CHECKOUT = True (the default) everything a rename or a redirector fixup is about to write is checked out first, through Unreal's own source control layer, so it works the same for Perforce, Git, SVN and Plastic.

  • It only checks out. It never submits, never reverts, never resolves: those are decisions for a person, not for a batch running over thousands of files.
  • Provider connected: files are checked out, the rename proceeds, the log says how many.
  • Provider offline: nothing is checked out; the affected files are listed and skipped with the hint to reconnect.
  • File held by someone else: listed with the server's own message and skipped. Everything else still runs. The tool never breaks a lock.
  • No source control: the setting does nothing.

Two people, one folder

When both run a fix on the same folder at the same time, the first check-out wins the exclusive lock; the second person's check-out fails, those files are listed with the reason and skipped. After the first submit the second person syncs and re-runs, and there is nothing left to do. If one of them is behind head, the check-out fails with sync first and the tool says so.

Keep Config/naming_check_rules.json under source control so everyone renames toward the same convention. Undo is per machine: you can undo your own run, not a teammate's.

Careful

Standard Unreal typemaps mark .uasset as exclusive check-out. If yours does not, two people can check out the same file and the conflict lands at submit time. That is a Perforce configuration matter the tool cannot compensate for.

14 / 19

Validation and import checks.

Cleaning up is half the job; the other half is not letting bad names in. The plugin registers a Data Validation hook that checks names when an asset is saved, when a changelist is submitted through the Submit dialog, and on right-click > Validate Assets. It uses the same evaluation as the Linter, so a name the Linter would flag is exactly the name validation flags. It only reports: nothing is renamed on save.

  1. Turn it on in the editor

    In Editor Preferences, Data Validation, enable validation on save and, if you want it at submit time, on submit. These are editor settings, not plugin settings.

  2. Choose the severity

    In the config file, VALIDATION_AS_ERROR = False makes a wrong name a warning in the Message Log that blocks nothing. True makes it an error: the Submit dialog refuses the changelist until it is fixed.

  3. Start soft

    Warnings while the team learns the convention, then switch to errors.

The message reads Naming: expected 'SM_Rock' for a StaticMesh (rule SM_). It stays quiet about excluded paths, skipped classes, classes with no rule and assets outside /Game. A Review asset is always a warning, never an error, whatever the severity: failing an asset over a name the tool itself will not decide would be unfair. If the check cannot run, the asset passes.

Note

A rename re-saves what uses the renamed assets. If those still have wrong names (material instances using renamed textures, say), validation on save reports them and Unreal shows its own Validation failed when saving multiple assets notification. That is these warnings, not a failed rename: rename them too, or switch validation on save off while you work through a project.

Check on import

Even earlier than save: when an import into /Game lands, the new assets are checked and one notification says how many break the convention, for example Naming Check: 12 of 40 imported assets need renaming, with up to three examples and an Open in Naming Check button that opens the Linter on exactly those assets. Forty textures dragged in at once give one notification, not forty. When nothing needs attention there is no notification, only a log line. Nothing is renamed.

It is opt-in. The first import of a session asks once:

ButtonDoes
YesTurns it on and checks this import right away.
NoTurns it off. Nothing more is asked.
Not nowCloses the question. Nothing is remembered; the next session asks again.

The answer is yours alone, kept per user and per project in the editor's settings, not in the team config. Change it any time on the Reports page with Check names after import and show a toast.

  • The Linter's status line, left of the buttons.
  • History: what was renamed, and the way back.

Known limits.

What version 1.1.0 does not do, or does differently from what you might expect:

  • Scan This Folder Only also scans the folder's subfolders, like Scan This Folder and Subfolders.
  • From the right-click menu, Check Folder Names, Version Style, Texture Resolutions and Mesh LOD / Nanite cover the whole project, not the selection.
  • Version Style V1/V2 to A/B also converts textures: T_Rock_V1 would become T_Rock_A, which reads as an alpha suffix. Preview first. The opposite direction skips textures.
  • The Suffix column on Rules > Class Prefixes is saved but not used for naming.
  • Folder Naming and Active Rules write to the Output Log only, without a CSV.
  • Folders are reported, never renamed. Renaming a folder moves every asset inside it and leaves one redirector per asset; the Folder Naming report shows that cost so you can decide which ones are worth it.
  • Skeletal mesh triangle counts in the mesh report come from the limited API Unreal exposes to Python and can differ from the editor's own figure; static mesh counts are exact. The report says which API supplied them.
  • Texture memory figures are estimates from resolution and compression format: a guide, not a profiler.
  • The journal is per machine, and Undo reverses only the latest run.
